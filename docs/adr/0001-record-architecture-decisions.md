# 1. Record architecture decisions

- **Status:** Accepted
- **Date:** 2026-11-21

## Context

Decisions made during planning and setup need to be easy to find and review,
for people and for coding agents working in this repo.

## Decision

Keep lightweight ADRs in `docs/adr`, numbered, one decision each, with status
Proposed → Accepted (or Rejected / Superseded by N).

## Consequences

Significant changes come with a new ADR. `docs/PLAN.md` stays the product plan;
ADRs record the reasoning behind technical choices.
