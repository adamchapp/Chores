# 9. Postgres + Drizzle, household-scoped tenancy

- **Status:** Proposed
- **Date:** 2026-11-21

## Context

Data is relational (households, kids, chores, submissions, ledger), and strict
isolation between households is critical.

## Decision

- **Cloud SQL for PostgreSQL 16**, with **Drizzle ORM** and SQL migrations generated by drizzle-kit and committed in `packages/db/drizzle`.
- Every household-owned table has a non-null `household_id` with `ON DELETE CASCADE`, so deleting a household erases all its data (right to erasure). Integration tests check this against a real Postgres.
- Postgres Row-Level Security is added in M1 as a second safeguard, alongside repository methods that always take a household ID.
- Migrations must be expand/contract safe so old and new revisions can run during a deploy.

## Alternatives considered

- **Prisma:** popular, but its heavier runtime and generated client make serverless containers bigger. Drizzle stays closer to SQL.
- **Firestore:** cheaper at zero scale, but a poor fit for relational data and transactional XP awards.

## Consequences

- The smallest Cloud SQL tier costs about £8–25/month even when idle; it doesn't scale to zero.
- The app currently connects with a password stored in Secret Manager (also in Terraform state, which sits in a private bucket). Moving to Cloud SQL IAM database auth to remove the password is a candidate for M7.
